# Agent instructions

Slack `/newintro` bot: books coffee and buddy intro meetings for new starters. Two AWS Lambdas (Python 3.13, arm64), DynamoDB, Secrets Manager. Docs index: [docs/README.md](docs/README.md).

## Commands

```bash
make venv     # .venv with the locked layer dependencies, boto3, pytest, ruff
make check    # the gate: ruff, pytest, tools/gen_diagram.py --check, tools/brand/check-icon.sh
make test     # pytest only (Secrets Manager, Slack, Google and Graph are stubbed)
make lint     # ruff only
make diagram  # redraw docs/assets/architecture-{light,dark}.svg
make build    # three Lambda ZIPs into dist/ (needs network and zip)
```

Run `make check` before and after every change; it is what CI runs.

## Layout

- `src/common/`: shared code, shipped as the `intro_common` layer package
- `src/ui_lambda/ui_entry.py`: Slack modal and request handler
- `src/worker_lambda/worker_entry.py`: books the meetings
- `scripts/`: `build.sh` (Lambda ZIPs), `cleanup_db.py` (merges duplicate DynamoDB users)
- `tests/`, `tools/` (diagram and brand generators), `docs/`

## Conventions

- Commits are conventional (`fix:`, `feat:`, `docs:`, `refactor:`, `ci:`, `chore:`) and authored by the repo owner. No co-author trailers, session ids or "generated by" lines in commits, PRs, issues or comments.
- Documentation must be true of the code: verify every command, flag and number, and keep no hand-typed counts that can drift.
- Never force-push `main`. Never commit secrets, keys, tokens, IP addresses, private hostnames or personal e-mail. The one public contact address is the one already in SECURITY.md.
- Directories `lowercase-kebab`, Python `snake_case`, shell scripts `kebab-case.sh`, docs `docs/lowercase-kebab.md`.
- Diagrams are drawn by `tools/gen_diagram.py`; edit the generator, not the SVGs.

## Do not change (runtime identifiers)

The `/newintro` command; config secret keys (`azure_tenant_id`, `buddy_azure_tenant_id`, `dynamodb_table_name`, `buddy_dynamodb_table_name` and the rest); env vars `CONFIG_SECRET`, `WORKER_FUNCTION_NAME`, `LOG_LEVEL`; the `intro_common` import name; DynamoDB table names `IntroUsers` and `BuddyUsers`.
